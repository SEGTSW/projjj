# Вимоги та симуляція

## Проблема

Система планування подій вирішує такі логічні задачі:

- створення подій з різними типами, пріоритетами, місткістю та нагадуваннями;
- перевірка конфліктів за учасниками, організатором і фізичною локацією;
- зміна події без втрати історичного статусу через версію;
- скасування з різними політиками, зокрема суворою політикою для critical-подій;
- сповіщення організатора й учасників через in-app, email та SMS канали;
- імітація сховища даних без зовнішньої БД.

## Актори

- Організатор: створює, змінює та скасовує події.
- Учасник: отримує запрошення, нагадування та повідомлення про зміни.
- Адміністратор календаря: керує блокуванням користувачів та правилами політик.
- Система сповіщень: доставляє повідомлення підписаним каналам.
- CI/CD pipeline: запускає тести, статичний аналіз і публікує звіти.

## Use Cases

1. Організатор створює подію з учасниками, локацією і нагадуваннями.
2. Система блокує створення події, якщо учасник уже зайнятий у цей час.
3. Система блокує створення події, якщо фізична кімната вже заброньована.
4. Організатор переносить подію, після чого учасники отримують сповіщення.
5. Організатор скасовує подію, а політика скасування перевіряє часове вікно.
6. Адміністратор блокує користувача, і такого користувача не можна додати до події.
7. CI/CD pipeline генерує JUnit, Sonar та coverage-звіти після кожного коміту.
